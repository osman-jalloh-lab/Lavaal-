# 2. CORE EXPERIENCE PRINCIPLES

## 2.1 Verified > huge

A smaller verified catalog is better than thousands of:
- invented models
- wrong variants
- old products surfaced as new
- mismatched photos
- duplicate SKUs
- unauthorized media

Scale should come from the pipeline, not from lowering standards.

## 2.2 Familiar first, deep second

The top-level Products overview must stay simple.

Customers should not face a massive database immediately.

Layer 1 is broad and visual.

Layer 2 is where the catalog becomes deep.

## 2.3 Quote-first commerce

LAVAALL is a sourcing marketplace.

The site does not need to pretend every product is live ecommerce inventory with a fixed checkout price.

Specific SKU:
- `Request Quote` should identify the exact model/variant.

Generic category:
- `Request Quote` is a sourcing request.
- Never imply an exact SKU was chosen.

## 2.4 Visual confidence

Product photography must make the catalog feel intentional, clean, credible, and high-end.

No noisy collage look.
No random retailer screenshots.
No unrelated lifestyle photos.
No generic â€œserver roomâ€ image standing in for an exact server.
No fake branded hardware generated by AI.

# 4. PRODUCT IMAGE ARCHITECTURE

This section is a hard visual contract.

## 4.1 Image purpose hierarchy

Images have different jobs:

### A. Overview/category imagery
Purpose:
- communicate a category instantly
- create visual polish
- not claim an exact branded SKU

Examples:
- fiber optic cable
- structured cabling
- televisions
- monitors
- cameras
- accessories
- compact refrigerator

These may use original/unbranded visual assets.

### B. Exact branded SKU imagery
Purpose:
- represent the actual product being quoted

These must come from a verified permitted source for that exact product.

### C. Gallery/detail imagery
Purpose:
- help customer understand form factor, finish, ports, dimensions, or variant

Use only source-permitted product media.

# 5. HOW PRODUCT PHOTOS SHOULD LOOK

## 5.1 General photography style

Preferred visual style:

- premium ecommerce product photography
- close-up
- isolated product
- white, off-white, very light neutral, or transparent background
- product centered
- product fills roughly 75â€“90% of the usable canvas when practical
- subtle realistic grounding/shadow
- clean edges
- no text overlays unless they are physically part of the product
- no promotional price stickers
- no retailer badges
- no screenshot chrome
- no watermarks unless unavoidable and explicitly permitted
- no busy room/lifestyle background for the primary product card
- no destructive crop

The product should look like something a buyer can evaluate.

## 5.2 Primary-image angle

Preferred order:

1. official main/front or 3/4 hero angle
2. alternate 3/4 angle
3. rear/side/ports/detail
4. another materially different useful product view

Avoid using four nearly identical rotations just to fill a gallery.

## 5.3 Product framing

For local display:

- use `object-fit: contain`
- preserve original aspect ratio
- never stretch
- never crop away ports, stand, screen corners, keyboard, antennas, or appliance edges
- give wide/tall products breathing room
- center optical mass, not merely the source image's pixel bounds

## 5.4 Resolution

For generated **generic category artwork**, target:
- approximately `1200 Ã— 800` WebP
- optimized for web
- visually sharp at card size

For **exact SKU imagery**:
- preserve the best permitted source resolution
- do not upscale by inventing hardware details
- web-normalize only as needed
- maintain source fidelity

## 5.5 Category artwork

Generic category art should be:
- unbranded unless branding is explicitly licensed
- product-focused
- one obvious subject
- premium catalog feel
- no random people
- no visual clutter
- no fake model number
- no fake logo

Good:
> a clean modern monitor isolated on white

Bad:
> a gaming room with neon RGB and six monitors when the card says â€œMonitorsâ€

## 5.6 Branded products

For Dell, HP, Lenovo, Samsung, LG, Hisense, TCL, Apple, etc.:

Do not generate a fake â€œexactâ€ model image.

Do not create a believable-looking chassis and label it as a real MPN.

Use:
1. permitted structured-source media
2. authorized manufacturer/distributor media
3. leave placeholder if rights/source are unresolved

Accuracy beats filling every image slot.

## 5.7 3D

True 3D product viewing is **not part of the current build**.

Future path:
- GLB / model-viewer
- only when legitimate model files exist
- separate modal/experience

Do not fake 3D by inventing unseen hardware sides.

# 6. IMAGE SOURCE & RIGHTS ORDER

Use this source priority:

1. **Permitted media from the product data source**
2. **Authorized distributor / manufacturer feed**
3. **Official manufacturer media with confirmed reuse permission**
4. **Original unbranded category art**
5. Placeholder

Never use production images from:
- Google Images scraping
- Amazon scraping
- Walmart scraping
- eBay scraping
- Back Market scraping
- random retailers
- hotlinked CDN URLs without permission

Search engines may be used for research/provenance discovery, but not as an automatic rights grant.

For every exact SKU image, preserve:
- source
- source product ID
- local file path
- media status
- whether restricted
- whether expired
- provenance
